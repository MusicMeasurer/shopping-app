# Переход на приватную проверку удаления аккаунта

- 044 рассчитана на действующий контракт удаления 039 и ACL 042. Проверку выполнить на изолированной базе. Для совместной выкладки с 043 отдельно подтвердить эксплуатационные проверки регистрации. Не пересоздавать keyring или IndexedDB при переключении и откате.
- Новый клиент с VITE_ACCOUNT_DELETION использует отдельный анонимный REST-клиент для статуса и подтверждения очистки. Проверить работу после отзыва токенов, включая потерянный ответ на подтверждение удаления, неактивную локальную копию и повтор после возврата сети. Проверить на существующей установке сохранение ID и секрета при обновлении.
- На переключении старый клиент теряет доступ к прежним RPC статуса и подтверждения снятия данных. Обновить PWA и проверить ревизию и service worker. При откате использовать сборку с поддержкой нового контракта. Публичную проверку по одному UUID не возвращать.
- Установки, сведения о которых уже удалены прежним 90-дневным процессом, восстановить из одной отметки удаления нельзя. Подтверждённая сессия исходного аккаунта регистрирует установку при открытии; неподтверждённые старые копии сохраняют локальные данные под исходным UUID. При новом UUID старая очередь не переносится. Не считать отсутствие доказательства подтверждением удаления.
- Резервное восстановление с внешним журналом удалений должно сохранять и объединять доказательства установок вместе с отметками и keyring. Для бессрочного экспорта достаточно UUID аккаунта, ID установки и keyed digest. Учёт подтверждений для напоминаний живёт отдельно по сроку. Проверить восстановление в изолированной среде до выпуска.
