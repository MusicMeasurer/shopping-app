# E4 · Личные списки и история покупок

## История покупок

Раздел архива показывает подтверждённые покупки с датой завершения, историческим названием списка, количеством и единицей. Поиск по названию товара работает по архивным снимкам текущего профиля. Регистр и лишние пробелы в запросе не влияют на результат. Записи остаются доступны после удаления исходного списка. Одноимённый новый список не меняет старые записи. Для связанного профиля без сети используется сохранённый архив аккаунта, если он уже загружен на устройство.

## Самостоятельное объединение списков

1. В меню личного списка пользователь выбирает «Объединить со списком», затем указывает список-получатель в том же профиле. Приложение показывает названия, тип получателя и предварительный результат. Временный и постоянный списки можно объединить, тип получателя сохраняется.
2. Совпадения находятся по тому же правилу нормализации названий, которое действует при добавлении товара. Для каждого совпадения пользователь выбирает, какую позицию оставить, или задаёт итоговые количество, единицу и отметку. Переносимую позицию также можно сохранить под новым именем. Имя проверяется относительно всех позиций итогового списка. Количества с разными единицами не складываются автоматически. Существующие дубликаты в получателе тоже показываются в предварительном просмотре.
3. Предлагаемое действие с источником — переместить товары и закрыть пустой список после подтверждения. История обоих списков сохраняется. В подтверждении явно указать, какой список исчезнет из активных. Если нужен вариант с сохранением источника, назвать его «Копировать покупки» и не смешивать с объединением.
4. Для независимого профиля применить результат одной транзакцией IndexedDB. Для облачных личных списков сервер проверяет владельца и версии обоих списков в одной транзакции. Повтор операции с тем же ID возвращает прежний результат. При новой правке или удалении любого списка обновить предварительный просмотр и запросить подтверждение заново. Существующий перенос профиля остаётся отдельной операцией.

Проверки включают совпадения с разными единицами, разными отметками и старыми дубликатами, историю после закрытия источника, повтор запроса, конкурентную правку и изоляцию профилей.

## Создание и завершение в локальной копии аккаунта · проект

- Создание. Новый список сразу доступен на устройстве для покупок. Черновик принадлежит только этому аккаунту и переживает перезапуск. Очередь сохраняет постоянный ID операции до отправки. После входа в тот же аккаунт сначала подтверждается создание, затем привязывается локальный список и отправляются его покупки. При конфликте названия черновик сохраняется, пользователь выбирает свободное имя. Автоматическая привязка по совпадению имени может отправить товары в чужой список того же аккаунта.
- Завершение подтверждённого облачного списка. Переиспользовать имеющуюся очередь завершений. Сохранять состав, отметки и выбранный режим. После входа в тот же аккаунт сначала отправлять правки товаров, затем проверять состав и ревизию списка. Если данные изменились, показать актуальный список и запросить повторное подтверждение. Запись в официальный архив приходит по серверной квитанции.
- Для интерфейса выбрать, как показывать завершение до получения квитанции. Предлагаемый первый вариант — пометить действие «Ожидает синхронизации» и дать отменить его до отправки. Вариант с немедленным скрытием списка требует отдельного представления ожидающего результата и возврата списка с правками при конфликте. Ожидающие покупки не должны попадать в подтверждённую историю.
- При завершении ещё не отправленного черновика сначала создать список в облаке, затем применить товары и завершение в порядке очереди. Сохранить единый результат даже при обрыве связи между операциями. Разовый и постоянный список после подтверждения используют свои текущие правила.

Приёмка должна проверить работу после выхода, перезапуск, вход в другой аккаунт без отправки чужого черновика, повторный вход в нужный аккаунт, конфликт имени, изменение списка на втором устройстве и обрыв после серверного подтверждения.
