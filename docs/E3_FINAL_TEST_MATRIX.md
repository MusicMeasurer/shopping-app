# E3 — финальный пакет проверок перед внедрением

Дата: 2026-11-07. Статус: **пакет подготовлен; принятие E3 не подтверждено**.

## Правило остановки
После успешного прохождения перечисленных автоматизированных проверок **не расширяем набор E3 новыми гипотетическими сценариями**. Новые идеи записываем в отдельный backlog после внедрения E3. Исключение: реальный дефект, падение CI, нарушение безопасности/целостности данных или обязательный критерий приёмки. Исправления дефектов перепроверяются, но не запускают бесконечный цикл расширения тестов.

| 6 | Очередь | Одновременный flush; не отправлять дубль | Existing unit |
| 7 | Аккаунты | Выход до отправки, при чтении очереди, во время RPC | Existing + batch unit |
| 8 | Аккаунты | Не подтверждать операцию после смены аккаунта | Existing + batch unit |

## Текущая граница достоверности
Пункты 1–18 можно закрыть CI при зелёном запуске после пакетных коммитов. Пункты 19–20 **не закрываются обычным CI**: требуются secrets и ручной запуск workflow в изолированном Supabase. Пункты 21–22 требуют реальной iPhone-приёмки; имитационные тесты не заменяют Siri/Shortcuts. Нельзя объявлять E3 внедрённым до выполнения обязательных критериев.

## Backlog после E3
Записывать сюда новые гипотезы, которые не являются обнаруженными дефектами, нарушениями безопасности или блокирующими критериями приёмки. Не добавлять их в текущий E3 test suite автоматически.
