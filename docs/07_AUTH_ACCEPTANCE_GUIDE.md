# Как закрыть регистрацию и восстановление доступа

Для этих действий нужен доступ владельца или администратора к проекту Supabase `shoppingapp-migration-lab`. Открой [полигон Supabase](https://supabase.com/dashboard/project/gmrqeubhotjpmtwokfeq) и сверь имя проекта и его ID `gmrqeubhotjpmtwokfeq`. Приложение для проверки будет на [интеграционном полигоне](https://musicmeasurer.github.io/shopping-app-preview/integration/). Проверка основной среды проводится отдельно после приёмки и разрешения на выпуск.

## 1. Выбери способ отправки писем

Для редактирования шаблонов на полигоне требуется собственный SMTP. Илья подтвердил, что настроил его 21 ноября. Если понадобится подключить другого отправителя, возьми у провайдера адрес сервера, порт, имя пользователя, SMTP-пароль и разрешённый адрес отправителя. [Документация Supabase по SMTP](https://supabase.com/docs/guides/auth/auth-smtp)

## 2. Настрой Auth в проекте полигона

1. В панели проекта открой **Authentication → Sign In / Providers** и параметры Email. Проверь, что Email включён, **Allow new users to sign up** включён, **Confirm email** включён. Сохрани изменения. Если включён отдельный запрет регистрации по email, разреши её для тестовой среды. [Настройки Supabase Auth](https://supabase.com/docs/guides/auth/general-configuration)
2. В параметрах безопасности паролей выставь **Minimum password length = 8**. При проверке используй уникальный тестовый пароль, который также удовлетворяет требованиям к составу, если они уже включены в проекте. [Безопасность паролей](https://supabase.com/docs/guides/auth/password-security)
3. Для подключения или смены отправителя в **Authentication → Emails → SMTP Settings** включи **Custom SMTP**. Заполни **Sender email** подтверждённым адресом, **Sender name** названием приложения, затем **Host**, **Port**, **Username** и **Password** значениями провайдера. Сохрани. Если интерфейс иначе группирует пункты, открой SMTP Settings по ссылке из документации. SMTP-пароль вводи только в поле Supabase. [Настройка отправителя](https://supabase.com/docs/guides/auth/auth-smtp)
4. В **Authentication → Emails → Templates** открой **Confirm signup**. Впиши тему «Код подтверждения ShoppingApp» и такой HTML:

   ```html
   <p>Код подтверждения регистрации в ShoppingApp:</p>
   <p><strong>{{ .Token }}</strong></p>
   <p>Введи его в окне регистрации приложения.</p>
   ```

5. Там же открой **Reset password**. Впиши тему «Код восстановления ShoppingApp» и отдельный HTML:

   ```html
   <p>Код восстановления доступа к ShoppingApp:</p>
   <p><strong>{{ .Token }}</strong></p>
   <p>Введи его в окне восстановления доступа в приложении.</p>
   ```

   Сохрани оба шаблона. Оставь обычный числовой код, лучше из шести цифр, если длина регулируется. В поле приложения поддерживаются 6–10 цифр. Для этого сценария пользователю нужен именно код из письма. [Переменные шаблонов Supabase](https://supabase.com/docs/guides/auth/auth-email-templates)

На iPhone, если нужная вкладка не помещается, в Safari можно запросить настольную версию сайта или открыть конкретную страницу из документации. В чат можно прислать скриншот без SMTP-пароля, ключей и одноразовых кодов.

## 3. Сообщи, что настройки сохранены

Достаточно написать: «Полигон `gmrqeubhotjpmtwokfeq`. Email и Confirm email включены, минимум 8, оба шаблона сохранены. Собственный SMTP настроен. Можно подготовить выкладку по инструкции 4». Для тестовой сборки нужна переменная **`VITE_ACCOUNT_EMAIL_CODES=true` на этапе сборки**. Её включает тот, кто собирает и выкладывает приложение. SMTP-пароль в GitHub или в переменные Vite переносить не нужно.

После выкладки открой полигон в Safari и проверь, что в окне входа появились «Создать аккаунт» и «Забыли пароль?». Если их нет, сообщи об этом вместе с точным адресом открытой страницы. Проверку доставки начинаем после подтверждения версии и привязки к БД полигона.

## 4. Проведи проверку на iPhone

Возьми новый тестовый адрес, к которому у тебя есть доступ. Для первого входа можно подготовить один независимый локальный список с узнаваемым товаром.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открой «Создать аккаунт». Проверь пароль из 7 символов, затем введи новый тестовый пароль из 8 и повтори его. | 7 символов отклоняются. С 8 символами можно запросить код, если пароль проходит настройки сложности. |
| 2 | Получи письмо «Код подтверждения ShoppingApp». Один раз введи неверный код, затем правильный из письма. | Неверный код не подтверждает адрес. Правильный возвращает к форме входа с сообщением о подтверждении. |
| 3 | Войди с новым паролем. Если был подготовлен локальный список, на запрос синхронизации ответь «Не синхронизировать». | Откроется новый облачный профиль. Локальный список доступен при возврате в независимый профиль. |
| 4 | Выйди и попробуй зарегистрировать тот же адрес. | Второй аккаунт не создаётся. Интерфейс даёт нейтральное сообщение и предлагает войти или восстановить доступ. Письмо при повторном запросе может не прийти, это не сбой доставки. |
| 5 | Открой «Забыли пароль?», укажи тот же адрес и получи письмо восстановления. Введи код и сохрани другой пароль. | Раньше ввода кода поля нового пароля нет. После сохранения открывается форма входа. |
| 6 | Убедись, что прежний пароль больше не подходит, затем войди с новым. | Открывается тот же аккаунт. Уже созданные в нём данные доступны. |
| 7 | При проверке собственного SMTP отдельно проверь «Запросить новый код». | Приходит новое письмо. Для подтверждения используй код из самого свежего письма. При лимите дождись разрешённого времени и повтори один раз. |

Проверь доставку с настроенным отправителем хотя бы на один тестовый адрес вне команды Supabase.

## 5. Если что-то остановилось

| Что видно | Что сделать |
|---|---|
| Письма нет | Проверь адрес, спам и лимит. Посмотри журнал доставки провайдера и Authentication Logs в Supabase за время запроса. |
| Письмо пришло со ссылкой или видно буквальное `{{ .Token }}` | Сверь, что сохранён нужный шаблон в том же проекте и что переменная вставлена без изменений. Запроси новое письмо. |
| Появилось «Слишком много запросов» | Дождись сброса лимита. На время отладки не нажимай «Запросить новый код» многократно. |
| Письмо пришло, но код отклоняется | Проверь, что открыто последнее письмо, адрес совпадает и код введён в правильном окне. Если ошибка остаётся, передай в чат точный текст и время запроса. |
| Пароль из 8 символов не принимается сервером | Сверь Minimum password length и действующие правила сложности в проекте полигона. Укажи в отчёте текст ошибки, без пароля. |

Чтобы зафиксировать приёмку, сообщи результаты по номерам шагов, браузер, время проблемного запроса и текст ошибки. Реальная доставка, повторная регистрация, восстановление и вход с новым паролем должны быть подтверждены отдельно от тестов с имитацией Auth.
