# 02 · Архитектура данных и ресурсов

**Редакция:** 2026-11-04 · целевая архитектура, без дублирования журнала испытаний.
**Назначение:** утверждённые принципы, текущая реализация, кандидаты и технические риски.  
**Важно:** не путать **реализовано**, **согласовано** и **гипотеза**.


## 1. Слои системы

```text
Siri / Apple Shortcuts ──> защищённый API [ПЛАН]
                                 │
ShoppingApp PWA ──> слой операций с данными ──> IndexedDB [РАБОТАЕТ]
                                 │
                                 └──> адаптер синхронизации ──> облачный сервис [ПЛАН]
                                                        │
                                           аккаунты, списки, права [ПЛАН]
```

- **Реализовано:** React + TypeScript + Vite PWA; GitHub Pages; локальное IndexedDB, базовые операции со списками, офлайн-доступ.
- **Согласовано:** offline-first; локальные личные списки без входа; после авторизации — облако, резервное хранение и совместные списки; разделение бизнес-логики и поставщика данных.
- **Не реализовано:** авторизация, облачная база, серверный API, синхронизация, общий доступ, обработка голосовой команды в целевом списке.

## 2. Модель данных

| Сущность | Локально | В облаке после входа | Примечание |
|---|---|---|---|
| Списки и позиции | Да, IndexedDB | Да, для синхронизируемых списков | Сейчас реализованы позиции с `id`, `listId`, `name`, `purchased`, `createdAt`; расширение модели требует миграции |
| Количество, единица, тип списка | План | План | Не вводить произвольные значения по догадке |
| Архив и версии завершения | План | План | Отдельные записи; не терять историю |
| Пользователь, участники и права | Не требуется для гостя | Да | Серверная проверка доступа обязательна |
| Очередь офлайн-операций | План | Синхронизируется | Повторная отправка не должна создавать дубли |
| Секреты и привилегированные ключи | **Нет** | Только защищённая серверная сторона | Никогда не в PWA или Shortcut |

**Границы хранения:** данные Safari и установленной iOS PWA могут находиться в разных изолированных хранилищах. Открытие URL из «Команд» в Safari не доказывает запись в базу установленной PWA. При отсутствии облака нельзя обещать единый список между ними.

## 3. Ресурсы и зависимости

| Ресурс | Статус | Назначение / ограничение |
|---|---|---|
| `MusicMeasurer/shopping-app` (GitHub) | Используется | Репозиторий кода, история, GitHub Actions; права записи помощников **не подтверждены** |
| GitHub Pages | Работает | Публикация `https://musicmeasurer.github.io/shopping-app/` |
| GitHub Actions | Работает | Сборка и деплой при push в `main`; проверять результат каждого выпуска |
| IndexedDB (`idb`) | Работает | Данные на устройстве; очистка данных браузера может их удалить |
| Apple Shortcuts / Siri | Частично испытано | Диктовка и запись файла при блокировке; URL открывается в Safari, в том числе при блокировке; полноценная запись товара не испытана |
| Codex | Временно недоступен | Разработка; ранее возникали ошибки доступа/сети; не считать возможность push гарантированной |
| Working Copy | Временный обходной путь | На iPhone push проверен; пробный Pro 10 дней, дальнейший бесплатный сценарий не подтверждён |
| Supabase | **Выбран для лабораторного прототипа; клиентская интеграция не готова** | PostgreSQL, авторизация, права, синхронизация; условия/лимиты проверить непосредственно перед подключением |
| Firebase / иной backend | Альтернатива | Потребуется адаптер и план миграции; прямой взаимозаменяемости API нет |
| Переводчик / API | Не выбран | Отдельное решение по качеству, офлайн и стоимости |

## 4. Обязательные принципы безопасности
- HTTPS/TLS при передаче; шифрование при хранении у провайдера проверяется отдельно. Это **не** означает сквозное шифрование.
- Авторизация для синхронизации и общих списков; вход не нужен для локальных личных списков.
- Права доступа проверяются на сервере / уровне базы (например, RLS при выборе Supabase), не только в интерфейсе.
- Siri отправляет запрос от имени конкретного авторизованного пользователя; **никаких service-role/admin ключей в Shortcut, клиенте или URL**.
- Предусмотреть ограничение злоупотреблений, безопасное хранение/отзыв токенов, идемпотентность запросов, обработку сетевых ошибок.
- Перед публичным запуском: проверка доступа между аккаунтами, политики удаления и экспорта данных, резервного восстановления и условий обработки персональных данных.

## 5. Синхронизация: решения до реализации
- Отдельный адаптер между UI и хранилищем; сохранение существующего локального поведения.
- Явные идентификаторы операций/объектов для защиты от дублей при повторах Siri и сетевых ретраях.
- Определить источник истины для синхронизируемых списков, стратегию конфликтов, порядок удаления и восстановления, границу локальных/общих данных.
- Определить миграцию гостевых списков при входе и выходе из аккаунта; исключить незаметную потерю данных.
- Сравнить стоимость не только по мегабайтам, но и по операциям, трафику, авторизации, активности и доступности.

## 6. Архитектурные решения (ADR, кратко)

| ID | Статус | Решение | Основание |
|---|---|---|---|
| ADR-001 | Принято | PWA на React/TypeScript, IndexedDB для первого прототипа | iPhone, скорость запуска, бесплатная публикация |
| ADR-002 | Принято | Гостевые локальные списки без регистрации | Низкий порог входа |
| ADR-003 | Принято | После входа — облачная синхронизация и семейные списки | Общие данные между устройствами и участниками |
| ADR-004 | Принято | Абстракция хранения/синхронизации; возможность смены провайдера | Уменьшение привязки к платформе |
| ADR-005 | Принято | Никаких платных сервисов без отдельного разрешения | Контроль расходов |
| ADR-006 | Кандидат | Supabase как облачная платформа для текущего прототипа | Изолированные лаборатории и SQL/RPC испытания; выпуск в рабочую среду отдельно согласуется |
| ADR-007 | Открыто | Способ безопасной авторизации Siri и работа при блокировке | Нужен прототип с реальным API |
| ADR-008 | Открыто | Конфликты, идемпотентность и миграция гостевых данных | Нужны проектирование и тесты |

## 7. Приглашения в общие списки — согласованная модель

- Владелец создаёт ограниченную по сроку одноразовую ссылку.
- Ссылку принимает **первый авторизованный пользователь, который ещё не является участником списка**; привязки к получателю нет.
- Владелец и существующие участники не могут принять ссылку; повторное использование и отзыв должны блокировать вступление.
- При передаче владения незавершённые приглашения отзываются атомарно.
- SQL 017 проверен в изолированной среде, но **пользовательская функция не выпущена**. Подтверждения и оставшиеся выпускные ограничения — в `05_DEV_LOG.md` и `07_MIGRATION_017_RELEASE_GATE.md`.
